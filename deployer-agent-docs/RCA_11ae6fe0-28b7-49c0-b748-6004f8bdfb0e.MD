# RCA — run 11ae6fe0-28b7-49c0-b748-6004f8bdfb0e (dev-foxy-pull)

## Verdict
Build failed at `build_image`. The cause is a **deployment-template / app-architecture mismatch**, compounded by an **unsupported database (PostgreSQL)**. This is NOT a manifest bug and cannot be fixed by editing the deployment manifests or by re-running the pipeline — it will fail identically. Handing back to E1.

## The failing step (real cause, not the red herring)
The trigger excerpt points at `Step #0 "restore-pip-cache": CommandException: No URLs matched: gs://.../pip-cache.tar.gz`. That is a **benign first-build cache miss** and is not what killed the build.

The actual failure is in the Docker build, frontend-build stage (from `get_build_logs`, build f92789a0):
```

#52 0.483 yarn install v1.22.22
#52 0.541 success Saved lockfile.
#52 0.558 Done in 0.08s.
#52 0.763 yarn run v1.22.22
```

`yarn install` resolved 0 packages (0.08s) and `yarn build` failed because the script does not exist.

## Root cause (confirmed in eph sandbox against this run's source at /app/scratch)
1. **Wrong template.** Deployment template = `fastapi_react_mongo_shadcn_base_image` (FARM: FastAPI + React + MongoDB). The FARM build does `COPY frontend/ → yarn install && yarn build` expecting a CRA/Vite React app in `/frontend`.
2. **The app is actually a Next.js app**, living at the repo ROOT, not in `/frontend`:
   - Root `package.json` → name `foxy-property-web`, scripts `dev: next dev`, `build: next build`, `start: next start`; deps include `next`, `react`, `next-sanity`, `mapbox-gl`, `pg`.
   - Root also has `.next/`, `next.config.js`, `next-env.d.ts`, `src/`, `tsconfig.json`, `postcss.config.mjs`.
3. **`/frontend` is a preview-only shim.** `/frontend/package.json`:
   - name `foxy-frontend-runner`, description literally: *"Emergent preview run-glue: launches the FOXY Next.js app (located at /app) on port 3000. Not part of the FOXY application source."*
   - Its only script is `start` (runs `next start` from /app). **There is no `build` script** → FARM's `yarn build` cannot work.
4. **Unsupported database.** The app uses **PostgreSQL**, not MongoDB:
   - `backend/.env` + `frontend/.env`: `DATABASE_URL=postgresql://foxy:...@localhost:5432/foxy`
   - root deps include `pg` / `@types/pg`; `.emergent` installs `postgresql`/`postgresql-contrib`.
   - Emergent's managed deploy provisions **MongoDB Atlas only**; there is no managed Postgres and `localhost:5432` does not exist in production. Even if the build is fixed, the app cannot reach its DB in production as written.
5. There is also a small FastAPI `backend/server.py` + `requirements.txt`, so the deployed shape is Next.js (frontend+SSR) + optional FastAPI.

## Why I did not attempt a manifest fix / redeploy
- Fixing this would require re-authoring the entire build for a different architecture (build the root Next.js app with `next build`, run `next start` on port 3000, disable nginx) — that is the job of the correct template, not a minimal manifest diff, and would not converge.
- No manifest edit can provision PostgreSQL. The DB dependency is unsatisfiable on the current managed stack.

## Required fixes
### 1) E1 / deployment setup (template) — Code/architecture
Recreate/redeploy this app with the correct **Next.js template** instead of FARM:
- If treated as Next.js-only: `nextjs_mongo_shadcn_base_image` (`next`).
- Since there is also a FastAPI backend: `nextjs_fastapi_mongo_base_image` (`nextjs-fastapi`).
The template is fixed at the start of the parent job; the Deployer agent cannot change it.

### 2) User — database (third-party)
The app is built on PostgreSQL, which Emergent's managed deploy does not provide. The user must either:
- Provision an external Postgres (e.g. managed cloud Postgres) and set `DATABASE_URL` to it as a deployment secret, **or**
- Migrate the data layer to MongoDB (the only DB Emergent provisions).
Until this is resolved, the app will have no working database in production even after the template is corrected.

## Not the cause
`restore-pip-cache` "No URLs matched" = first-build cache miss, benign.
